## Findings

**F1 [P3][S] Unlock celebrations switch the front-end music to the scoreboard loop.**
- **Cause:** `HerdLobby._play_flair_celebration` (HerdLobby.gd:1677) and the circuit-unlock celebration in `ArenaSelect` (ArenaSelect.gd:980) emit `EventBus.match_won` to reuse the fanfare. `AudioManager._on_match_won` also calls `play_music(MUSIC_SCOREBOARD)`.
- **Effect:** after a NEW FLAIR card (or a circuit unlock), the lobby and arena select loop `scoreboard.mp3` instead of `title.wav` until the next match.
- **Evidence:** probe `am_music` read `scoreboard.mp3|on` at the lobby at gt 813/843 (after the GOLDEN JETSTREAM card, `WK-176_13_change_setup.png`). An eval in arena select returned `scoreboard.mp3`. The swap happened again in the Trials shell flow at gt 4228.
- **Repro:** on a fresh profile, bank 10 herd KOs in Brawl → Pause → CHANGE SETUP → the NEW FLAIR card drops → read `AudioManager._music.stream.resource_path`.
- **Fix idea:** give the celebration its own sting call, or a `match_won` flag that skips the music change. Owner: sound-designer or ui-ux.

**F2 [P3][S] Recurring ArenaRenderer warnings on every stage.**
- **Counts:** "no grass decal tufts yet" and "no decal_flower_white yet" appeared 131 times each in 86 min rendered (322 each headless). The `_warned` dict is per ArenaRenderer instance, and each stage builds a new renderer, so "warn once" fires once per stage.
- **Wrong text:** "missing res://assets/world/bumper_post.png — grey mat strip stand-in" appeared 103 / 221 times. The file exists. `_paint_bumper` (ArenaRenderer.gd:1189) uses it only for **vertical** bumpers, so every horizontal bumper takes the placeholder grey-strip path and logs a misleading "missing" line.
- **Impact:**
  - About 2-3 warning lines per stage bury real warnings in the run log.
  - Horizontal bumpers still render as the placeholder (seen in Bumper Gauntlet, Wrecking Yard, the Trials courses and the sports courts).
- **Fix idea:** make `_warned` static (one line per process), and reword or retire the bumper warning. Owner: gameplay-programmer, with art-director to decide whether horizontal bumpers need art.

**W1 [watch] Object count creeps about +20-25 per match under gbplay `eval` polling only.** Headless without the harness was flat. It doesn't affect players. If anyone cares: check whether `McpInteractionServer._cmd_eval`'s per-call `GDScript.new()` scripts are retained.

**Headless-only noise (not findings):**
- 5x `Condition "!actions.custom_samplers.has(...)"` at boot from the dummy renderer's shader compiler. It does not appear in the rendered log.
- At quit: "32 ObjectDB instances leaked" / "12 resources still in use". This was a mid-match `quit()` with runtime-compiled harness scripts, so it was not attributed. Run once with `--verbose` if anyone wants it.

**Fixture note:**
- Trials "Hammer Vigil" (SURVIVE 12 s with a spinning hammer) stalled the idle fixture player for more than 5 min. That is by design: Trials has no clock and the course can only be cleared by surviving.
- The `SOFTLOCK?` line in the drive log is this fixture case, not a game softlock.

## WK-174 verdict: NOT REPRODUCED. Close as a harness artefact.

**Setup:** Rocketball lobby with keyboard + pad 0 + pad 1 joined, so FORMAT is locked at 2V2 (`WK-174_00_rb_lobby_3humans.png`).

**Clean reps, 30 of 30:** View/TAB → left x3 on the locked FORMAT row → down x2 → ramped stick (or S) down x2 → close. Inputs were frame-accurate and injected in-game.
- Pad 0: 10/10. Pad 1: 10/10. Keyboard: 10/10.
- Every rep gave rows `[0, 0, 1, 2, 0, 1]`, as expected for 3 rows, and left no stuck holds.
- Stills: `WK-174_01_rules_left3_down1.png` (CPU SKILL focused) and `WK-174_02_rules_down2.png` (PRESSURE NETS focused).

**Cause of the CD5 symptom:** D-pad auto-repeat (`lobby_repeat_delay` 0.40 s, `lobby_repeat_rate` 0.09 s) plus wrap-around (`posmod`) on the 3-row panel.

| D-pad down hold (ms) | 150 | 450 | 600 | 650 | 750 | 1000 | 1200 |
|---|---|---|---|---|---|---|---|
| Rows stepped | 1 | 2 | **3** | 4 | 5 | 8 | 10 |

- A 600 ms hold steps exactly 3 rows and lands back on FORMAT.
- gbplay `raw gamepad` press + release are two TCP calls about 0.6-1 s apart, so each "tap" is really a hold. That reproduced "focus didn't move" in 2 of 3 sequences (one press 0→2, the next 2→2).

**Design note for WK-46 (not a bug):** repeat wraps past the last row. Consider clamping on auto-repeat and wrapping only on a fresh press.
