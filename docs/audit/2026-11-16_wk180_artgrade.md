### B-F1: short posts draw a squashed pearl ("lens slit") (Fix)
- **Evidence:** s3_pinball_alley, the 120x260 post between the two grass platforms (15, 20a, 20b). Crop: pearl, then a thin eye-shaped slit, then pearl.
- **Cause:** `ThreeSlice.build` units branch (`src/systems/ThreeSlice.gd:51-62`).
  - At cap 0.20 each cap already holds one pearl.
  - The centre span is 9.6 px, but `total = maxi(1, roundi(span / unit))` forces one unit, so `ku = 0.12`. That one pearl gets squashed to 12% height.
  - The same thing happens to any post or rail whose centre span is under about 0.85 of a unit.
- **Fix (units mode only; the classic `units == 0` path is unchanged):**
  1. Let `C2 = 2.0 * cap_len` and `U = tile / units` (display px).
  2. Let `x = maxf(0.0, (along_tgt - C2) / U)`.
  3. For `P` in `{floori(x), ceili(x)}`, compute `k_P = along_tgt / (C2 + P * U)`.
  4. Pick the `P` with the smallest `absf(log(k_P))`.
  5. Draw **everything** at along-scale `k = k_P`, caps included:
     - top cap at pos 0, `len cap_src`, k;
     - then `P` units laid out cumulatively, as whole 5-unit tiles plus a remainder tile of `rem` units (source offset `cap_src`, as now), all at k;
     - bottom cap at `along_tgt - cap_len * k`.
  6. Let the tile run extend 1 px under each cap, and keep caps listed last so they draw on top.
  7. The worst case is k of about 0.88 or 1.14 (P=0 vs P=1), so pearls never visibly distort. Long rails come out at k of about 1.00, so they are unchanged.
  8. In units mode only, change the cap-crop branch condition (`ThreeSlice.gd:35`) from `along_tgt <= 2*cap_len + 0.5` to `along_tgt < 0.85 * 2.0 * cap_len`.
- Expected results:
  - 120x260 (pinball_alley) → P=0, k=1.02: two pearls between two collars, no slit.
  - 100x420 (bumper_gauntlet) → P=3, k=1.005.
  - 120x190 (s3_keyhole) stays on the crop path: a stubby one-stud post (17). That reads fine; keep it.
- Put the 0.85 in Tuning: `wk182_units_min_cap_k = 0.85`.

- **Fix (offline PIL pass, originals untouched):**
  1. For `assets/world/grass/decals/tuft_a_fit.png` and `tuft_b_fit.png`, crop to rows 0-72 inclusive (69x73).
  2. Multiply the alpha of rows 69, 70, 71 and 72 by 0.8, 0.6, 0.4 and 0.2, so the stems fade into the dirt instead of ending on a hard cut.
  3. Overwrite the two `_fit` files and re-import them.
  4. Add a CATALOG note: "WK-180 grade D-F1: bottom 7 rows (baked soil patch) cropped + 4-row alpha fade".
  5. Leave the Tuning values alone. The sprite bottom is still the stem base, so `wk180_tuft_base_off` 6 still applies.

## 4. WK-182: square bumpers ("stacked donut")

- **Dropshot 90x100 floor corners** (08, 10, 11): the same macaron under each wall post.
- **Cause:** h >= w routes to the vertical post. The post's two caps alone are 1.93x the width (2 x 200.6 rows at width scale), so every square falls into the cap-crop path.

### Options rejected
- **Scale `bumper_block` (1.205) onto squares.**
  - `build_whole` caps the width fudge at 0.9, so a 120x120 square draws about 5.5 px past the collider on each side.
  - Forcing a non-uniform fit is a 17% horizontal squash at 1:1 and 25% at 90x100. The pearls go visibly oval and the side outline thins.
  - The pearls are the family read, so this is a no.
- **Derived row-extrusion of `bumper_block`** (mocked offline). There is no clean panel row between the pearl rows. Extruding the lid bands works, but it leaves vertical "brushed" streaks and a drawer-like lid. Use it only as a last-resort fallback (below).

### Decision: new generated sprite `assets/world/bumper_block_sq.png` (1:1)
- **Refs (ChatGPT, STA clipboard paste):**
  1. `assets/world/bumper_block.png` flattened on white. This is the primary ref; the edit must be "the same object, made square".
  2. `assets/world/bumper_post.png` flattened on white.
  3. `assets/reference/style_north_star.png`.
- **Prompt** (append the base style suffix from `docs/briefs/arena_rendering.md` §"Base style suffix" verbatim, then "square 1024x1024"):
  > "Using the first attached image as the exact object, material and line-weight reference: redraw the SAME chrome bumper
  > block, but perfectly SQUARE (1:1 width to height), straight-on side view, for a cartoon game. Keep everything else identical:
  > the rolled light-silver top band with its bright top-left highlight (#D9DDE3), the darker rolled bottom band (#6E7684),
  > the mid silver-grey glossy body (#98A1AF), rounded corners (corner radius about 25% of the side), and the recessed inner
  > panel holding a 2 by 2 grid of big glossy white (#F4F6F9) pearl studs with thin dark-grey socket rings and a small top-left
  > specular dot on each, identical to the studs in the attached images. The four studs should fill the panel evenly with equal
  > margins on all four sides. Same thick dark-chocolate (#3B241B) outline weight as the attached block. Symmetrical, no screws,
  > no text, no logo, no drop shadow, no ground."
- **Intake:**
  1. `python tools/art.py keyout <dl> <tmp> --tol 45`
  2. `trim`
  3. `resize 300` (to 300x300; aspect must be 0.97-1.03 after trim, else re-roll)

  - there is any shadow or ground;

  - Derive it from `bumper_block.png` by duplicating source row 37 x25 and row 232 x26 (the lid bands). That gives 300x300.
  - Then box-blur only the inserted rows horizontally (radius 3), excluding the outer 12 px columns, to kill the column streaks.

## 5. WK-182: corner tufts on wide-void arenas (three_meadows, two_hills: frames 22, 23)

**Decision: keep the tufts. Retire the void-lip suppression.**
- **Why:**
  - `paint_void` returns immediately (`ArenaRenderer.gd:1331-1335`, owner floating-islands ruling 2026-07-19). No pit, canyon wall, hazard rim or chevron is drawn anywhere.
  - The §6.3 suppression exists so a cheerful tuft never contradicts a drawn hazard lip. With no lip drawn, it only suppresses at invisible void-rect edges.
  - That is why grassy_expanse's two inner gap ends are bare (29) while every other island end in the game, including three_meadows and two_hills, has a tuft. The difference is arbitrary to the player.
  - The tufts sit entirely below the landing line (R0 holds), so they cost no readability at the edge.
- **Rule:** an end's decals are suppressed only if that end carries visible hazard art (rim, chevrons or canyon wall). A sky drop is not hazard art.
- **Implementation:**
  1. Add `Tuning.wk182_void_lip_suppress: bool = false`.
  2. Wrap the void-rect loop at `ArenaRenderer.gd:1017-1023` in `if Tuning.wk182_void_lip_suppress:`.
  3. Leave a comment that it must be turned back on if `paint_void`'s pit block is ever re-enabled.
- **Expected result:** grassy_expanse's inner gap ends gain their tufts, and daisies may come within 60 px of those ends.
